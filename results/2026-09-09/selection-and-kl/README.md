# 정책 선택 자동화와 갱신 제한, 그리고 감시–중지 연결

검토 의견의 순서대로 구현했다. **새 학습은 시작하지 않았다.** 기존 세 실행에
선택 절차를 적용해 검증만 했다.

## 1. 정책 선택 자동화 — 원본 BC를 후보에 포함

`scripts/select_approach_policy.py`. 후보는 **원본 정책과 모든 체크포인트**이고,
두 단계로 고른다.

1. 평균 행동 1회로 home에서 완주하는가. 못 하면 후보에서 제외한다(샘플 평가도 하지
   않는다).
2. 남은 후보를 공통 개발 seed(기본 100–119)·공통 std(0.05)로 샘플 평가한다.
   완주 수가 가장 큰 것을 고르고, **동률이면 원본**을 고른다. 원본을 이기지 못하면
   원본을 반환한다.

기존 세 실행에 적용한 결과다. 평가는 정책 파일 내용 해시로 캐시한다.

| 실행 | 후보 | 반환 | 개선 |
| --- | --- | --- | --- |
| A / seed 0 | BC 13/20, 40,960 13/20, 51,200 14/20, **61,440 20/20**, 71,680 평균행동 실패 | `policy_step_00061440.pt` | **예** (20/20 대 13/20) |
| A / seed 1 | BC 13/20, 40,960 13/20, 51,200 9/20, 61,440 이후 전부 평균행동 실패 | **BC** | 아니오 |
| B / seed 0 | BC 13/20, 40,960 13/20, 51,200·61,440 평균행동 실패 | **BC** | 아니오 |

- A/1의 51,200은 **평균 행동으로 완주하면서 샘플 9/20**이다. "깨지기 직전
  체크포인트를 채택"했다면 BC보다 나쁜 정책을 골랐을 것이고, 이 절차는 BC를 돌려준다.
- 각 실행의 40,960(=warm-up 끝, actor 미갱신)이 BC와 같은 13/20을 낸 것은 초기화와
  평가 경로가 일치한다는 확인이다.
- 회귀 테스트 5개: 개선 후보 선택, 이기지 못하면 원본 반환, 동률 시 원본,
  평균 행동 실패 후보 제외(샘플 평가도 하지 않음), 후보별 해시 기록.

## 2. 갱신 후 KL 측정과 갱신 취소

기존 KL 로그는 각 optimizer step **직전** 비율들의 평균이라 마지막 갱신 후의 변화량이
아니었다. 이제 한 update가 끝난 뒤 **같은 rollout 상태에서** 갱신 전 log-probability와
비교해 KL을 다시 계산하고(`kl_after_update` 열), `--kl-limit`을 넘으면 그 갱신을
되돌린다.

되돌릴 때는 **actor·critic·log_std와 optimizer 상태를 함께 복원**한다. 가중치만
되돌리면 Adam이 거부된 스텝의 모멘트를 그대로 들고 있다가 다음 갱신에서 적용한다.
회귀 테스트로 (a) 갱신 후 KL이 완성된 정책에서 측정되는지, (b) 복원 후 optimizer
상태까지 초기화되는지, (c) 같은 상태에서 두 번 갱신하면 동일한 결과가 나오는지를 고정했다.

KL 제한은 갱신을 억제하는 장치일 뿐이며, 완주 보장은 계속 폐루프 평가로 확인한다.

## 3. 감시와 중지 연결

`scripts/watch_approach_training.py`. 새 체크포인트를 평균 행동으로 평가하고,
실패하면 (a) 기준 정책을 다시 확인해 환경 문제와 정책 퇴행을 구분한 뒤 (b) 실행
디렉터리에 `STOP`을 쓴다. 학습 루프는 매 rollout 시작 시 이 파일을 확인하고 종료한다.

밤 실험에서는 감시와 중지가 분리돼 있어 B는 51,200 실패 후 66,560까지, A/1은
61,440 실패 후 상한 102,400까지 학습했다. 이 연결로 같은 일이 반복되지 않는다.

## 4. β 증대는 보류

지적대로 현재 항은 **BC의 출력이 아니라 원래 시범 라벨**에 가까워지게 한다. BC 자체도
시범 라벨과 평균 0.0117의 오차가 있으므로 β를 키우면 출발점부터 바뀐다. 또한 시범
전체의 평균 오차가 작다고 접근 끝부분이 보존된다는 보장이 없다. 이번 결과로
"β가 작아서 실패했다"고 결론내지 않는다.

- 전체 테스트 **329 passed**(선택 5개, 갱신 3개 추가). 변경 파일 Ruff 통과.

  backward·optimizer step 0회는 그대로다.

## 다음: 규칙을 고정한 반복 실험

준비는 끝났다. 제안하는 설정은 다음과 같다(실행 전 확인 요청).

- 조건 A(정책 LR 3e-5, critic LR 3e-4, warm-up 40, β 0) + `--kl-limit`
- 학습 seed 3–5개, 각 102,400스텝 상한, 감시가 실패 시 자동 중지
- 각 seed마다 선택 절차를 돌려 **그 절차가 반환한 정책**을 평가 대상으로 삼는다
- 최종 평가는 아직 쓰지 않은 새 seed 묶음(예: 2000–2019)
- 보고: seed별 반환 정책(BC인지 체크포인트인지), 개선 여부, 붕괴 지점

`--kl-limit` 값은 밤 실행의 갱신 후 KL을 아직 측정하지 않았으므로 첫 seed에서
측정값을 보고 정한다(로그의 `approx_kl` 0.004–0.020은 갱신 전 값이라 그대로 쓰지 않는다).
