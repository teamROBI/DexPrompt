# P3 결과 교차 검토

새 학습·수집·동적 재실행 없이 기존 산출물과 코드를 검토했다. 캔 성공은 확인했고,
보고서의 일부 해석과 검사 도구를 수정했다. 원본 NPZ·manifest·funnel.json은 보존했다.

## 확인한 결과

- 원본 artifacts.json의 파일 5개 SHA256 모두 현재 파일과 일치.
- 캔 성공과 재현 NPZ 모두 `b4ddabc29bd969e8e582c61e5d9a095abe1b7f6611d16fba3b813645cdb91a9e`.
- 두 데이터셋 `validate_dataset` 통과, 각각 accepted=1. 단일 물체 그룹이고 val/test가
  없어 `training_ready=false`. 재현본을 새 독립 시범으로 세지 않는다.
- 캔 시범: 1,251 tick, 상승 약 108.75 mm, 종료 시 5/5 군, 전 군 접촉 493 tick,
  최대 손가락 힘 22.703637 N, 최대 침투 **1.99980373 mm**. 2 mm 한계까지 여유는
  약 **0.00019627 mm**로 사실상 경계값이다. 품질 기록의 말단 접촉 유지 시간은 1초.
- 배치 기록을 절대 허용오차(rtol=0)로 재검사해도 세 물체 build/reset 비교는 일치.
  안정화 이동은 병 0.1044 mm, 카메라 0.0440 mm, 캔 2.5075 mm.

## 집계와 해석 정정

| 물체 | 실행 시도 | 고유 teacher 파일 해시 | 완주 시범 | 귀속 누락 |
| --- | ---: | ---: | ---: | ---: |
| 캔 | 32 | 30 | 1 | 0 |
| 카메라 | 17 | 13 | 0 | 0 |

별도 `reproduce`는 위 분모에 포함하지 않았다. 고유 후보 수는 teacher 파일 내용 기준이며,
새 물체 수·예측 후보 수·서로 다른 기하학적 파지 수와 동일하지 않다.
유형별 예측·보존·정련·선별 합과 기존 성공 수치는 원 보고서와 일치했다.
새 [funnel.json](funnel.json)은 기존 실행 파일에서 재집계했다.

카메라 `14_Tripod`는 **최대 3/3 군 동시 접촉 78 tick**, **종료 시 2/3 군**이다.
닫기 시간초과 5건의 전 군 동시 접촉은 0 tick이 맞지만, 리프트 시간초과 7건은 모두
동시 접촉 이력이 있다. 품질 명령 실패 5건 중 마지막 기록 phase가 close인 것은 4건,
lift인 것은 1건이다. 따라서 접촉 획득과 유지, 품질 제약에 따른 명령 실패를 분리한다.
마지막 phase는 실패 직전 기록이며 guard 내부에서 어떤 제약이 후보 명령을 모두
막았는지까지 특정하지 않는다. 제어 또는 teacher 형상 단독 원인이라는 주장은 미입증이다.

Pincer 두 후보의 실패만으로 캔 전체에 그 유형이 부적합하다고 확정할 수 없다.
정련 후 테이블 관통 104/165·39/63은 개선할 큰 탈락 지점이지만, 테이블 인지 정련의
완주율 개선은 같은 입력을 사용한 별도 비교가 필요하다.

## 수정한 코드와 검증

- `tests/test_teacher_collection.py`: 테스트 Recorder에 실제 인터페이스의
  `visual_profile=None` 반영. 최초 확인은 **3 failed, 29 passed**였고 3개 모두 같은
  속성 누락이었다. 실제 Recorder는 이 속성을 항상 초기화한다. 운영 수집기의 실패를
  숨기는 기본값 처리를 추가한 것이 아니다.
- `report_multiobject.py`: 에피소드에 저장된 후보 해시·유형을 우선 사용한다. 원본 후보
  파일이 있으면 기록된 해시를 검증하며, 귀속 보완에는 episode의 candidate index를
  사용한다. 시도 배열의 행 번호는 여러 yaw/검증 탈락 때문에 후보 번호와 다를 수 있다.
  최대 접촉군·마지막 phase·고유 후보 수·귀속 누락 수를 별도 출력한다.
- `placement.py`: NumPy 기본 상대 허용오차가 절대 허용오차를 완화하지 않도록
  `rtol=0` 명시. 작은 위치/회전/scale 차이를 놓치던 경우를 회귀 테스트로 고정했다.
- `check_placement.py`: Recorder는 rest=0을 생성하고 공통 build는 yaw를 적용하지
  않는다. 구현되지 않은 nonzero rest/yaw는 실행 전에 거부한다. 현재 범위는 공통
  build 대 reset 비교이며 모든 단계 산출물의 독립 감사라고 표현하지 않는다.
  다른 놓임 자세를 시도하려면 생성·필터·정렬·실행 전체의 rest 전달을 먼저 구현해야 한다.

관련 테스트 **102 passed** (teacher collection, placement, multiobject/chain report,
visual observation/memory, teacher replay, execution, recorder state). 새 회귀 테스트는
배치 5개·집계 3개이며, 기존 테스트 3개 실패도 해결했다. 변경 Python 파일 Ruff 통과,
`git diff --check` 통과. 전체 테스트 모음의 무오류를 주장하지 않는다.
