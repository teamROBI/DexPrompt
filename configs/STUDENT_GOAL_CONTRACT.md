# 시각 student의 입력·목표·행동 계약

2026-09-09. 이 문서는 teacher 수집과 student 구현이 맞춰야 할 경계다.
현재 검증 범위는 [student 검토 보고서](../results/2026-09-09/student-readiness/README.md)를
참조한다. 목표를 이해하는 학습된 모델이나 언어 grounding의 성공을 선언하지 않는다.

## 한 제어 tick의 데이터

| 필드 | 저장 형태 | 의미 |
|---|---|---|
| `rgbm[t]` | H×W×4, uint8 | 명령 적용 전 head RGB와 현재 보이는 목표 물체 mask |
| `right_cam_img[t]` | H×W×3, uint8 | 같은 상태의 wrist RGB |
| `right_state[t]` | 27 관절 | 같은 상태에서 측정한 팔 7+손 20 관절 위치 |
| `action[t]` | 27 관절, 원본 float64 | 다음 제어 구간에 실제 적용한 절대 actuator 위치 목표 |
| `timestamp[t]`, `control_dt[t]` | 초 | 관측 시각과 명령 유지 간격(현재 0.02초) |
| `part_mask[t]` | 선택적 H×W, uint8 | 현재 보이는 물체 mask에 포함되는 요청 부위 mask |

새 `observation_version=2`에서는 아래 필드도 필수다. 기존 v1 데이터와 모델은 별도
경로로 유지하며, 누락된 wrist mask를 관측한 0으로 대체하지 않는다.

| 필드 | 저장 형태 | 의미 |
|---|---|---|
| `wrist_mask[t]` | wrist H×W, uint8 | 손목 카메라에서 보이는 목표 물체 |
| `wrist_part_mask[t]` | wrist H×W, uint8 | 손목 카메라에서 보이는 요청 부위. 물체 지시이면 0 |
| `target_pixels[t]` | int32, 4 | head 물체·head 부위·wrist 물체·wrist 부위의 원본 픽셀 수 |
| `target_visible[t]` | uint8, 4 | 같은 순서의 가시성 0/1. 실제 mask와 일치하는지 검증 |

학습 입력은 시각 관측과 측정 관절 상태다. teacher 목표 pose, phase, 접촉 정답,
물체 world pose, 성공 판정은 정책 입력으로 전달하지 않는다. 물체 pose를 사용해 만든
시뮬레이션 정답 mask는 **oracle grounding 입력**으로 분류한다. 이는 이미지에서 목표를
자동으로 찾아냈다는 증거가 아니다.

Teacher의 중력 보정이 이미 `action`에 포함돼 있으므로 student 명령에 다시 더하지 않는다.
시범 원본은 재현을 위해 float64를 보존하고, 모델 입력만 float32로 변환한다.
관절 순서와 제어 간격은 학습 manifest와 실행기가 같아야 한다.

`EpisodeChunks[t]`는 시점 t 관측과 `action[t:t+H]`를 묶는다. v2는 여기에 시점 t까지
실제로 보인 목표 기준 관측을 추가한다. 현재 기본 H=64,
재관측 전 실행 길이는 8이다. 에피소드 끝에서 다른 시범으로 넘어가지 않고 유효 구간을
mask로 표시한다. 손실 계산은 무효 행동값을 정규화 공간의 0으로 치환해 attention 입력을
통한 누설도 차단한다. 정규화 통계는 train 시범에서만 계산한다.

## 목표 표현

| 요청 | `condition` | 모델 입력 |
|---|---|---|
| 물체 지정 | `kind=object`, 정확한 `object_id` | 물체 mask 유지, 부위 mask=0, `part_present=0` |
| 부위 지정 | `kind=part`, `object_id`, `part_id`, 주석 귀속 | 물체 mask와 별도 부위 mask, `part_present=1` |
| 물체 선택 point | 명시된 이미지/카메라 좌표에서 목표 물체로 grounding | 위 물체 조건으로 변환 |
| 부위/접촉 point | 물체 선택점과 구분한 입력 모드·영역 정의 | 위 부위 조건으로 변환하고 영역 접촉을 평가 |
| 언어 | 대상/부위 grounding 후 위 조건으로 변환 | 원시 문자열은 현재 action 모델에 직접 들어가지 않음 |

`object_id`·`part_id`는 현재 API의 귀속과 목표 변경 감지에 쓰이며, 텍스트 임베딩으로
모델에 주입되지 않는다. 새로운 부위/물체 요청은 남은 action chunk를 버리고 즉시 재계획한다.
추적 때문에 mask 픽셀이 매 프레임 변하는 것은 같은 요청의 갱신이며 매번 요청 ID를 바꾸지 않는다.
같은 ID로 다른 부위를 재지정하는 UI를 추가한다면 명시적 요청 revision을 condition에 포함해야 한다.

부위 mask는 물체 mask의 부분집합이어야 한다. 물체 전체 mask를 임의로 부위 mask로
대체하지 않는다. 수집에서는 수동 object-local 부위 주석의 scale/bounds를 실제 자산과
대조하고, 같은 주석 영역으로 물리적 접촉을 판정한다. 영상의 특정 픽셀을 두 그룹으로 나눈
이번 routing fixture는 의미 부위 주석이나 파지 성공 자료로 사용하지 않는다.

## 가려짐과 해상도

- `part_present`는 **부위 지시의 존재**이며 부위의 현재 가시성 표시가 아니다.
  요청 부위가 가려져 mask가 0이어도 1을 유지한다.
- 목표 물체 mask가 0인 관측도 존재한다. 현재 코드가 이를 허용한다고 해서 가려짐 중
  목표를 잘 유지하는 정책을 검증한 것은 아니다.
- v1에는 현재 관측 한 장만 들어가며 요청 ID의 임베딩도 없다. RGB/관절 상태가 같고
  두 요청 부위의 mask가 모두 0이면 입력이 구별되지 않는다. v2에는 아래의 별도 기준
  관측을 연결해 이 표현 한계를 보완했다. 학습된 파지 성능 검증은 아직 남아 있다.
- 기존 진단 시범은 64×64, 새 시각 시범은 원본 256×256다. 모델의 518×518 확대는
  원본에 없는 세부 정보를 복원하지 않는다. 카메라와 해상도 설정을 데이터에 기록한다.

### Mask 소실 진단 이후의 구현 기준 — 2026-09-09

[재현 진단](../results/2026-09-09/mask-visibility/README.md)에서 기존 MuJoCo visible-mask
생성 결과와 저장본의 일치를 확인했다. 빈 mask를 데이터 오류로 일괄 삭제하거나,
로봇을 숨겨 얻은 물체 실루엣으로 덮어쓰지 않는다. 후자는 가림 원인을 확인하는
진단용 정답이며 현재 RGB에서 보이는 mask가 아니다.

아래 기능은 [visual-goal-v2](../results/2026-09-09/visual-goal-v2/README.md)에서
수집·cache·학습 입력·모델·온라인 추론까지 구현하고 무학습 검증했다.

1. 새 수집은 원본 RGB/segmentation을 같은 카메라·같은 해상도에서 렌더링한다.
   native 256×256와 head 하향 구도를 작은 비교의 시작점으로 삼고, 실제 카메라의
   장착·보정값 및 다른 물체/배치에서 검증한 뒤 공통 설정으로 확정한다.
2. 두 카메라의 물체/부위 visible mask와 각각의 가시성·픽셀 수를 구분한다.
   head와 wrist는 각 카메라의 segmentation 및 depth 투영으로 독립 계산한다.
3. 각 요청마다 카메라별 **첫 유효 목표 관측**을 보존한다. 부위 요청은 해당 부위가
   보일 때만 기준 관측을 얻는다. 기준은 배경을 지운 정사각형 물체 crop(RGB+물체/부위
   mask), 원본 영상의 정규화된 bbox, 그때의 측정 관절 상태다. 같은 모양 물체라도 최초
   위치 정보를 잃지 않도록 bbox를 유지한다. 재등장해도 기준을 덮어쓰지 않는다.
   나중에 처음 보인 두 번째 카메라의 기준은 그 시점부터만 추가한다.
   이전 프레임 mask를 현재 픽셀 좌표의 정답인 것처럼 복사하지 않는다.
   `goal_reference_policy`로 유효성 기준을 checkpoint config에 기록한다. 병·캔 진단은
   native mask 최소 64픽셀, bbox 각 축 최소 4픽셀, 영상 가장자리 2픽셀 띠에 포함된
   물체 mask 비율 최대 10%다. part 요청의 크기는 part mask로 판단한다. 완전한 물체
   관측이나 최적 참조를 보장하는 규칙은 아니다. 누락 시 기존 1픽셀 기준을 유지한다.
   온라인/오프라인 모두 같은 함수를 사용하며, 채택 전 프레임에는 참조를 넣지 않는다.
4. 기억용 기준 관측은 실행 중 실제 얻은 관측에서 만든다. 미래 프레임·teacher pose·
   물체 world pose를 정책의 기억 입력으로 넣지 않는다. 같은 장면에서 두 목표가 모두
   가려져도 요청별 조건이 구별되는지와, 폐루프에서 올바른 목표를 잡는지를 따로 검증한다.

`GoalMemory`는 요청 변경/revision 변경과 `actor.reset()`에서 초기화한다. 새 요청 또는
두 번째 카메라 기준의 최초 획득 시 남은 action chunk도 버리고 재계획한다. 새 요청의
유효 기준이 양쪽 모두 없으면 명령을 생성하지 않고 사유를 반환한다. 이전 요청의 기억은
재사용하지 않는다. 카메라별 최초 관측이 t보다 늦으면 학습 입력에서도 그 기준은 0이며
`goal_valid=0`이다. `goal_images`/`goal_boxes`/`goal_state`/`goal_valid`는 과거의 기준
관측으로부터 만들어지며 현재 가시성과는 별개다.

기준 crop은 224×224로 전처리하고 공유된 frozen ViT-B로 인코딩한다. 물체와 부위의
mask 가중 특징, 기준 bbox·측정 상태·유효성, 현재 카메라별 가시성을 action transformer에
전달한다. 기준 관절 상태도 train-only state 통계로 정규화한다. `part_present`는 요청의
의미를 그대로 유지한다. 관측 전체 시퀀스를 기억하는 recurrent 정책은 구현하지 않았다.

목표가 처음부터 보이지 않는 에피소드의 prefix는 `EpisodeChunks` 진단에서 제외할 수
있지만, home부터의 학습용 preflight는 그런 데이터를 명시적으로 거부한다. 미래에
보이는 목표를 reset 시점에 소급 적용하지 않는다. 현재 검증 시범은 모두 초기 head에서
목표가 보여 제외된 prefix가 0이다.

## 다음 작은 부위 실험의 통과 조건

1. 같은 물체·같은 배치에서 두 개의 서로 다른 **실제 object-local 부위**를 정의한다.
2. 두 요청 각각에 대해 접근·닫기·리프트와 요청 부위 접촉을 만족하는 teacher 시범을 확보한다.
3. 같은 이미지·관절 상태에서 요청만 바꿨을 때 조건 채널이 올바르게 바뀌는지 검사한다.
4. 학습 후 동일 장면에서 요청만 바꿔 행동·접촉이 달라지고 두 과제가 각각 완주하는지 확인한다.
5. 정답 mask와 예측 mask 평가를 구분하고, 가려짐·해상도·grounding 실패를 따로 보고한다.

1–2번 없이 3번의 tensor 변화만 확인한 것을 의미 이해나 부위 조건부 파지 성공으로 세지 않는다.
