  lecun 환경·모델 로드·기록 행동 4/4 대조군은 통과했다. 본 정책 평가는 정상 종료했다.

   같은 seed에서 겹치는 병의 궤적·물리 배치·목표 조건·판정 계약도 비교한다.
2. 첫 20–50 tick을 기록 행동과 비교한다. 27관절 순서·단위·정규화·absolute action,

   어느 관절과 어느 body가 먼저 과도하게 움직이고 충돌하는지 확인한다.
3. 동일한 저장 관측에서 학습/추론 전처리와 목표 참조를 비교한다. 관측 오차와

   실측이 있어야 원인으로 채택한다.
4. 학습 없이 확인할 계약/구현 오류를 먼저 해결한다. 대조군·성공 기준은 유지한다.
5. 그다음 학습이 필요하면 고정 시범 하나의 재현 진단을 먼저 설계한다. 기존 4시범 실험과
   별도 이름·예산으로 실행하고, 한 번에 한 요인만 바꾼다. 추가 학습은 이 문서만으로
   시작하지 않는다. loss 감소만으로 다음 단계에 넘어가지 않는다.
6. 완료 조건: 카메라+정답 목표 mask+관절 상태만으로 home→닫기→지속 lift,
   teacher 실행기 인계 없이 같은 물리 기준을 통과한 폐루프 결과. 한 과제 통과는
   진단용 이정표이며 일반화 증거는 아니다.

### 전달문

우리 목표는 Dexonomy의 정식 파지 유형·접촉 지식을 보존한 전체 시범을 다양한 형상에서
확보해 시각 student로 전이하는 것이다. 손가락 5 초기값 진단은 종료한다.
다음 작업은 같은 그릇·망치의 **정식 파지 유형 변경을 통한 제한된 데이터 확보**다.

1. 기존 음성 6후보의 반복 수·PIP·루트 미세조정을 더 하지 말 것.
   물체별 새 유형은 최대 2개만 고른다. 실제 템플릿과 요구 body를 읽고, 형상에 대한
   선택 근거를 먼저 기록한다. `33_Inferior_Pincer`, `14_Tripod` 등을 검토할 수 있으나
   이름만으로 접촉 구성을 추정하지 말 것. 기존 유형에서 손가락 5를 삭제하는 것은 금지한다.
   적은 손가락의 새 유형이 성공해도 기존 5지 유형을 해결한 것으로 쓰지 말 것.

2. 실행 전에 계획과 입력 해시를 저장한다. 같은 물체의 예측 pose 묶음을 공유하고,
   object/mesh/scale/rest=0/yaw=0/world 배치·테이블·선택 규칙을 고정한다.
   align seed 0/1/2, 정련 반복 400을 모든 새 조건에 동일하게 적용한다.
   matcher·keep·roll/depth·IK 설정도 기록하고 조건 사이에 바꾸지 않는다.
   과거 50회 결과와의 차이를 유형 효과로 해석하지 말 것.
   기존 400회 기록도 입력·다른 설정이 다르면 참고값으로만 제시한다.
   이 작업은 엄밀한 유형 인과효과 입증보다 성공 데이터 확보를 우선한다.

3. 예산은 물체 2개 × 새 유형 최대 2개 × align seed 3개,
   각 조합에서 정련으로 보내는 초기화 최대 12개다(최대 144개, 패딩/중복 별도 집계).
   실제 후보 선택은 결과를 보기 전에 고정한다. 접근→닫기→리프트는 물체당
   고유 teacher 후보의 최초 실행 최대 12개, 합계 최대 24개만 실행한다.
   양성 대조군 2회와 새 성공의 물체당 재현 1회(최대 2회)는 별도이며,
   동적 실행 전체 상한은 28회다.
   전체 실행 시간 상한 4시간과 개수 상한 중 먼저 닿는 쪽에서 멈춘다.
   상한은 탐색 예산이며 완주를 보장하는 시간 예측이 아니다. 상한 때문에 미실행한
   조건은 실패와 구분해 별도 기록한다.

4. 먼저 검증된 병·캔 대조군을 각 1건 확인한다. 대조군이 깨지면 확대하지 말고
   설정/구현 문제를 확인한다. 새 유형은 정식 전체 요구 접촉군, 기존 충돌·침투·힘·
   리프트·유지 기준으로 판정한다. init 파일 존재를 필터 통과로 세지 않는다.
   padding 전 판정, contact 탈락 뒤 QP not_run, 원본 후보 귀속을 보존한다.

5. 정련 통과 후보만 기존 정적 선별→검증된 home 접근→닫기→리프트로 연결한다.
   성공은 동적 전체 실행과 필요 접촉 유지로만 인정한다.
   새 형상에서 성공하면 동일 manifest/seed로 재실행하고 원본/재현 해시를 기록한다.
   검증된 시범은 해당 형상/배치의 개발 데이터로 표시한다. held-out으로 다시 쓰지 않는다.

6. 모두 실패하면 유형·물체·예산·게이트를 추가로 바꾸지 말고 종료한다.
   정렬/재도달/정련 필터/정적 검사/접근/접촉 획득/유지 중 어느 단계가 막혔는지
   분모와 함께 보고한다. 그릇·망치를 물리적으로 불가능하다고 결론내리지 말 것.
   이후 다른 물체로 넘어갈지 결정할 수 있도록 근거만 정리한다.

7. 변경은 teacher 관련 최소 범위로 제한한다. student·visual·mask·goal-memory·PPO·
   실행 성공 기준과 lecun 프로세스는 수정하지 않는다. 공용 서버에서 CPU worker 2,
   BLAS/OMP/MKL 1, nice 15 수준을 유지하고 tmux로 실행한다. 다른 사용자 GPU가
   필요해지는 작업은 자동으로 시작하지 않는다.

8. 보고서는 `results/2026-09-10/type-expansion/README.md`에 쓴다.
   계획 대비 실행/미실행, 단계별 분모, 물체/유형별 전체 완주, 접촉·힘·침투 여유,
   원본 해시·귀속, 재현, 관련 테스트를 포함한다.
   PAPER_TODO의 P3만 근거 링크와 함께 갱신하고 P5/전체 상태는 덮어쓰지 않는다.
