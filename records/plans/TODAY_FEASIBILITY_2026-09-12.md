# 오늘의 판정 실험 — Dexonomy 시범 편집과 시각 실행

2026-09-12. 최신 사용자 요청: 오늘 안에 가능성을 판단해야 하며 심층 진단보다 공개 방법 재사용을 우선한다.
**이 작업서는 이전 Claude/Codex 7시간 준비서보다 우선한다.** 시작 시각 T0와 종료 시각을 기록하고
최대7시간 안에 결과를 낸다. 이 문서 작성은 실험이나 학습이 시작됐다는 뜻이 아니다.

## 무엇을 결정하나

1. Dexonomy reference의 작은 편집이 HX5 전체 파지 실행의 실제 개선으로 연결되는가?
2. 기존 시각 BC가 알려진 학습 장면에서라도 카메라 입력으로 완주하는가?

문헌은 시범 편집 RL→시각 모방학습이라는 구조의 근거로 받아들인다.
오늘 미지 물체 일반화·모든 지시·논문 채택 가능성을 증명하려 하지 않는다.
공식 clone과 코드 확인은 [기록](../experiments/2026-09-12/demofungrasp-reference/README.md)에 있다.

## Claude에게 전달할 명령

이전 7시간 작업서의 선정 원장 전면 정리·선정 모델 학습 준비·추가 guard 심층 진단을 보류하고,
DemoFunGrasp식 시범 편집의 **물리 실행 가능성**을 먼저 확인해줘.

1. 45분 이내에 `third_party/demofungrasp/tasks/grasp.py`의
   `generate_reaching_plan_idx`와 `algo/ppo_onestep/{ppo,storage}.py`를 보고,
   기존 MuJoCo/HX5 실행기에 작은 reference 편집 adapter를 구현한다.
   원 Isaac Gym 환경 전체 설치나 손 모델 교체는 하지 않는다.
2. 기존 HOPE A에서 각 물체 하나씩의 실패 조건을 사전에 고정한다.
   AlphabetSoup/Peaches/Raisins의 기존 실행 원장에서 인프라 오류가 아닌 최초 실패 후보를
   정해진 순서로 고르고 출처·유형·좌표·시작 상태를 기록한다. 원장에 필요한 데이터가 없으면
   그 물체는 차단으로 보고하고 실패 후보를 계속 바꿔가며 고르지 않는다.
   비교는 같은 후보·같은 장면에서 zero-edit 대 nonzero-edit다.
3. 먼저 기존 성공 대조군 3건과 선택한 실패의 zero-edit 3건을 실행한다.
   zero-edit는 기존 행동/판정을 보존해야 한다. 실패하면 최소 수정에 최대45분만 쓰고,
   여전히 맞지 않으면 해당 경로 차단으로 보고한다. 그 상태에서 편집 결과를 해석하지 않는다.
4. 첫 행동 공간은 손목 reference의 물체 초기 좌표 기준 이동·회전만 사용한다.
   각 실패 조건에 같은 8개 편집을 미리 고정한다:
   x ±5 mm, y ±5 mm, z +5/+10 mm, z축 회전 ±5°.
   이동/회전은 reference의 어떤 구간에 적용되는지 먼저 고정하며 home은 유지한다.
   접근과 파지 reference가 서로 어긋나지 않게 적용하고, 원 리프트 변위는 유지한다.
   손 관절 목표·유형·필수 접촉군은 변경하지 않는다.
   이는 원 논문의 전체 손 모양 편집보다 좁은 **행동 공간 사전검사**다.
5. 기존 IK/경로 검증과 접촉 피드백 close→lift→hold 및 품질 기준을 그대로 쓴다.
   물체를 이동시키거나 고정 손 목표 추종으로 바꾸거나 실패를 임계값 완화로 통과시키지 않는다.
   평가용 목표 접촉군은 실제 목표 물체 접촉으로 측정한다.
6. 대조/zero-edit 6회 + 편집 24회 + 첫 개선 재현 최대3회 = 최대33회.
   접근 실패도 분모와 실행 비용에 포함한다. 성공한 편집은 같은 조건으로 한 번 재현한다.
   원본/기존 시범/student 데이터는 보존하고 새 출력만 사용한다. tmux에서 실행한다.
7. T0+5시간에는 새 실행을 멈추고 집계/재현/인계한다. 남는 예산을 새 물체·새 유형·
   더 많은 편집이나 controller 튜닝으로 채우지 않는다. 최초 실행 시간으로 완료 예상도 갱신한다.

필수 결과는 물체별 zero-edit/편집 완주, 최대 높이가 아닌 hold 포함 성공,
접촉 준수·침투/힘 여유, 물리 실행 수·시간, 편집 좌표/값·후보 해시다.
손목 편집에 반응이 없더라도 전체 DemoFunGrasp의 손 모양 편집이나 연구 자체가 불가능하다고 쓰지 않는다.
성공 시범이 늘면 **편집 학습에 유용한 행동 공간을 찾았다**고 판단한다.
이는 고정 제안 탐색이며 RL 학습 성공이 아니다. 새 RL 학습은 이 결과와 실행 속도를 보고 다음으로 잇는다.

## Codex의 같은 시간 작업

- 첫45분: lecun의 기존 최종 checkpoint/평가를 회수한다. 불가능하면 인증/산출물 문제로 표시한다.
  현재 확인 가능한 마지막 접속 결과는 `Permission denied (publickey)`다. 서버 학습 실패가 아니다.
  인증이 안 되는 동안 다른 서버에서 대신 학습하거나 접속 재시도를 반복하지 않는다.
- 기존 평가가 있다면 재실행하지 않는다. 없다면 같은 데이터/카메라/목표 입력/기존 평가 설정으로
  사전 고정 최종 checkpoint를 작은 폐루프 평가에 연결한다. epoch13·seed1000–1002의 기존 계약을 유지한다.
  과거의 중간 checkpoint와 현재 학습 결과를 혼동하지 않는다.
- 비교군은 성공 teacher 실행과 student다. student 실패면 최초 이탈의 입력/action/좌표만 짧게 확인한다.
  새로운 시각 backbone·VLA·보상·BC 변형을 동시에 구현하지 않는다.
- 공개 DemoFunGrasp의 one-step 인터페이스와 우리 결과를 연결해 다음 학습 명세를 짧게 작성한다.
  학습은 lecun에서만 한다. 오늘 새 장시간 학습을 준비 작업의 자동 후속으로 시작하지 않는다.
- 남는 시간에만 Raisins clutter2건을 기존 intake로 별도 검사한다. 이것을 오늘 판정의 선행조건으로 삼지 않는다.

## 당일 결론 규칙

| 결과 | 판단과 다음 일 |
| --- | --- |
| 2개 이상 조건에서 실패→완주가 재현됨 | 편집 RL 구현/학습을 우선 진행할 실용적 근거. 일반화 증거는 아님. |
| 1개 조건만 개선 | 제한된 긍정 결과. 해당 작은 환경에서 one-step 학습 검증으로 이어감. |
| zero-edit 정상, 편집 개선0 | 시험한 작은 손목 편집은 미지원. 다음은 논문처럼 손 모양 편집까지 포함하거나 생성 경로 변경. 동일 후보 미세 튜닝 반복은 중지. |
| zero-edit 재현 불가 또는 실행 준비 지연 | 연결 구현 미완료. 아이디어 실패로 판정하지 않고 실제 차단 지점과 남은 시간을 보고. |
| student가 학습 장면에서 완주 | 시각 전이의 최소 근거. 다음은 물체/배치별 분리 평가. |
| teacher만 완주, student는 모두 실패 | 2단계 전이 병목이 남음. 1단계 데이터 생성의 가능성과 분리해 결정. |
| lecun 미접속/최종 결과 누락 | student 결과 미확인. 기존 보고 수치로 대신 결론 내리지 않음. |

2개라는 기준은 오늘의 자원 배분 결정 규칙이며 통계적 유의성 기준이 아니다.
새 논문의 기여는 단순 DemoFunGrasp 재구현이 아니라 Dexonomy 지식의 선정·적응 효과와
그 데이터의 지시 조건 시각 전이로 검증해야 한다. 오늘은 그 첫 실행 근거를 확보한다.
