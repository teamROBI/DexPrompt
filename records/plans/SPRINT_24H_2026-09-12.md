# 24시간: 자동 시범 → 시각 행동 → 목표 변경 최소 검증

기준 시각: 2026-09-12 20:00 KST. 보고 마감: 2026-09-13 20:00 KST.
사용자 요구는 전체 단계 1~4를 빠르게 진행하는 것이다. 성공 여부는 실험 결과로 판정한다.
이 계획은 미지 형상 일반화나 논문 전체 완성을 24시간 내 보장하지 않는다.
학습은 lecun에서만, 긴 실행은 tmux에서, 기존 자료와 공통 물리·성공 기준은 보존한다.

## 마감에 답할 질문

1. 정확한 형상·Dexonomy 후보에서 시범을 자동 생산·검증·인계할 수 있는가?
2. 중복·물리 cohort·입력 정렬을 관리한 시각 학습 데이터가 준비됐는가?
3. 카메라·목표 mask·허용된 관절 상태만으로 학습 정책이 리프트와 유지까지 수행하는가?
4. 같은 장면과 같은 로봇 초기 상태에서 목표만 바꾸면 지정 물체를 잡는가?

학습 선정기의 기준선 대비 우위, 편집 RL의 이득, 미지 형상 일반화는 별도 항목이다.
규칙 기반 후보 선택으로 1번의 생산 경로를 연결해도 학습 선정·적응이 검증됐다고 쓰지 않는다.
Point/Language→mask 연결 성공과 최종 행동 성공도 별도 판정한다.

## 현재 확인된 상태

- 이번 teacher 49건 중 정확한 중복 5건, 신규 44건. 기존 포함 61건은 teacher 원장 수다.
  Milk B와 clutter가 포함돼 있으므로 61건 전체를 A 단일 조건 학습 풀로 합치지 않는다.
- 기존 A12 student 자료는 보존한다. 새 49건의 접촉 인수 검사는 47통과·2보류다.
  보류 2건은 신규 AlphabetSoup x−10 mm와 yaw−7.5°, 후보 057c04e1이다.
  따라서 신규 44건 중 보관 접촉 검사 통과는 42건이며 시각 인수는 아직 진행 중이다.
- Turing `codex-followup-intake`: 시각 재현→cache→입력 감사→대조군→preflight 진행 중.
- 최근 공식 행동 backend의 고정 과제 BC는 0/3이었다. 같은 설정 재학습을 성과로 세지 않는다.

## 담당 및 시간 배분

### Codex: 데이터·student·목표 입력

**0~3시간 (20:00~23:00): 인수와 실험 입력 고정**

- 실행 중 인수를 확인한다. 6후보의 첫 항목을 우선하며 오류가 있는 경로는 수정·검사 후
  새 출력에 재시도한다. 원시 실패 기록은 남긴다.
- Claude의 중복 원장을 episode SHA로 연결한다. 중복 시범을 학습 가중치나 평가 표본에 중복 반영하지 않는다.
- 첫 실험에는 인수된 시범을 사용하고 처리 중인 전체 47건을 기다리느라 지연하지 않는다.
- 작은 폐루프 진단과 배치 일반화 평가를 구분한다. 알려진 학습 과제의 성공을 확인할 때는
  학습 과제임을 표시한다. 별도 배치 평가는 scene/배치 그룹을 통째로 분리한다.
- 이미 결과를 본 teacher 후보 풀을 독립 미지 형상 시험으로 다시 쓰지 않는다.

**3~6시간 (23:00~02:00): 행동 오차·복귀 데이터 단일 가설 구현**

- 기록 행동 양성 대조와 학습/추론 관측·행동 시간 정렬을 같은 시작 상태에서 확인한다.
- 현재 상태에서 teacher가 다시 계산한 행동으로 돌아오는 시범을 수집할 수 있는지 작은 규모로 검사한다.
  과거 궤적 행동을 단순히 복사해 교란 상태의 expert 정답이라고 쓰지 않는다.
- 복귀 시범이 구현되면 0교란 대조를 먼저 확인하고, 사전에 정한 작은 교란 8개까지만 실행한다.
  성공 기준을 통과한 시범만 학습에 쓰고 실패도 전부 기록한다. 교란 부여와 성공 판정 변경은 구분한다.
- 3시간 안에 유효한 복귀 데이터를 만들지 못하면 '복귀 데이터 미확보'로 표시한다.
  미구현 가설을 실행 완료했다고 보고하거나 근거 없이 학습부터 반복하지 않는다.

**6~12시간 (02:00~08:00): lecun에서 제한된 BC 비교**

- 복귀 데이터가 확보되면 고정된 관측·행동 모델로 원래 데이터 대 복귀 추가 데이터 비교를 한다.
  기존 체크포인트가 데이터/설정 계약까지 동일한 비교군인지 확인하고, 아니면 불일치를 명시한다.
- 변경은 데이터 조건으로 제한하고, 출력 방식·sampler·학습률·성공 게이트를 동시에 탐색하지 않는다.
- checkpoint 선택은 개발 결과로만 하고 최종 평가 seed/조건은 미리 고정한다.
- 시범 재생 성공, 학습 손실, 접촉 획득, 전체 완주를 따로 보고한다.
- 이 경로에서 알려진 과제 완주가 나오지 않으면 지시 기반 파지까지 성공했다고 주장하지 않는다.
  남은 시간에는 실패 원인과 목표 입력 경로 검증을 정리하며 무제한 재학습하지 않는다.

**12~20시간 (08:00~16:00): 목표 변경 및 작은 배치 평가**

- 폐루프 성공이 있으면 인수된 다물체 시범으로 같은 장면 목표 전환을 평가한다.
- 목표 mask만 바꾸는 비교에서 물체 배치·카메라·로봇 초기 상태는 동일해야 한다.
  유형별 열린 손 자세가 달라 정답 유형을 드러내는 조건은 같은 시작 상태 비교가 아니다.
- Point는 클릭 좌표, Language는 물체 선택 지시로 해석한다. simulator 정답 mask를 사용하는
  oracle 연결 검사와 실제 이미지 grounding을 구분한다. 고정 이름 lookup을 언어 일반화로 부르지 않는다.
- 목표를 못 찾음, 다른 물체를 선택함, 접근 실패, 파지/유지 실패를 분리한다.

**20~24시간 (16:00~20:00): 결과 고정·최종 판정**

- 새 학습 시작은 중단하고 기존 평가·보고를 마친다.
- 1~4 각각을 구현/실행/성공/미검증으로 구분한다.
- 미지 형상·실물 전이·논문 기여 비교는 후속 과제로 남기고, 알려진 물체의 데모를 일반화로 확대하지 않는다.

### Claude: 최소 다물체 teacher 인계 (사용자가 전달할 후속 지시)

- 기존 인계 감사는 완료로 유지한다. 학습 선정기/편집 RL 추가 튜닝은 이번 24시간의 선행 조건으로 두지 않는다.
- 같은 A 물리의 안정된 2물체 장면을 고정하고, 같은 초기 로봇 상태에서 목표만 변경하는
  teacher 시범 확보를 담당한다. 우선 같은 파지 유형의 AlphabetSoup·Peaches를 검토한다.
- 목표별 후보 최대 2개, 배치 최대 3개, 새 동적 실행 최대 12회. 단일 물체 대조 최대 2회,
  성공 재현 최대 6회를 별도로 기록해 총 상한 20회다. 결과를 보고 배치/기준을 완화하지 않는다.
- 장면이 같아도 목표 변경 때문에 brace·손 자세가 달라지면 계약 미통과로 보고한다.
  강제로 초기 상태를 덮어쓰고 경로가 검증됐다고 가정하지 않는다.
- 목표 접촉/방해물 접촉·이동을 따로 기록하고 완주 성공만 별도 HANDOFF로 전달한다.
- 일부 성공만 확보돼도 2시간 안에 1차 인계한다. 4시간 상한에 도달하면 결과를 마감한다.
- 실패하면 목표 전환 teacher 자료 미확보라고 보고하고 student나 공통 제어 코드는 변경하지 않는다.

이 Claude 작업은 계획일 뿐이다. 사용자가 전달하거나 실제 실행 기록을 확인하기 전에는 실행 중으로 쓰지 않는다.

## 실행 상태의 진실

이 계획 작성 시 실제 실행 중인 것은 기존 시각 인수 tmux뿐이다.
복귀 시범 구현·새 BC·Point/Language 연결·다물체 teacher 후속 실행은 아직 시작하지 않았다.
작업별 실행 manifest와 결과가 생길 때만 상태를 갱신한다. 계획과 백그라운드 실행을 혼동하지 않는다.
