# P3 다물체 시범 — 캔은 확보, 카메라는 미확보

병(기존 성공)을 기준선으로 두고 카메라와 캔을 개발 물체로 추가했다. 기본 놓임
자세(`rest_index=0`), yaw 0, 단일 물체 장면, 기존 검증 경로
(관측 → GraspGenX 예측 → 필터 → 정렬 → `op=grasp_admm` → 정적 선별 → 실행)를 사용했다.
**정적 통과를 완료로 세지 않았다.** 완료는 실행기가 접근·닫기·리프트·유지를 마치고
현행 품질 기준을 통과한 시범이다.

**캔에서 검증된 전체 시범 1건을 확보했고, 카메라에서는 확보하지 못했다.**
이번 완료 조건(병 외 두 물체)은 절반만 달성했다.

교차 검토: 실행 32/17회는 반복을 포함한 시도 수이며, teacher 파일 해시 기준
고유 후보는 캔 **30개**, 카메라 **13개**다. 별도 `reproduce` 실행은 여기에 포함하지
않았다. [교차 검토 기록](../multiobject-crosscheck/README.md)에 원본 대조와 수정 근거를 남겼다.

## 1. 배치 계약 — 모든 단계가 같은 곳에 세우는지 확인

`icra.placement`가 물체마다 mesh sha256, 컴파일된 scale, rest index, yaw,
world 변환, scene 파일 해시를 기록하고, `scripts/check_placement.py`가 장면을
공통 `scene.build` 경로와 `Recorder.reset` 경로로 다시 만들어 비교한다.
이번 검사는 **rest=0, yaw=0의 두 구성 경로 비교**이며, 모든 단계의 실제 산출물을
독립적으로 대조한 것은 아니다. 다른 rest/yaw는 아직 두 경로에 일관되게 적용되지
않으므로 검사 CLI에서 명시적으로 거부한다.

| 물체 | 단계 간 배치 | 놓은 뒤 안정화까지의 이동 |
| --- | --- | --- |
| 병 | 일치 | 0.10 mm, 0.00° |
| 카메라 | 일치 | 0.04 mm, 0.04° |
| 캔 | 일치 | 2.51 mm, 0.05° |

안정화 이동은 불일치가 아니라 물리다. 다만 **정적 선별은 놓인 자세에서, 실행기는
안정화된 자세에서** 판정하므로 캔은 2.5 mm 다른 배치를 평가한다는 뜻이고, 기록에 남겼다.
회귀 테스트 8개로 계약을 고정했다(다른 rest index·scale·mesh·scene을 불일치로 잡는다).

## 2. 단계별 탈락 — 분모를 남긴 funnel

`33_Inferior_Pincer`만으로 시작했고(항목 3의 "소수 후보"), 전부 탈락하면 원인을
확인한 뒤 확대했다. 확대는 두 번 했다.

**확대 1 — 후보 수.** 신뢰도 상위 20개만으로는 카메라 0개·캔 5개가 남았다.
카메라의 20개는 IK를 통과한 254개 변형이 **전부 테이블과 충돌**했다(`world x` 손·손가락).
예측 전체(77·109개)로 넓히자 카메라 12개, 캔 72개가 남았다. 원인은 상위 신뢰도
자세가 테이블에 가깝다는 것이지 물체가 불가능하다는 것이 아니었다.

**확대 2 — 파지 유형.** Pincer는 캔에서 실행 완주 0이었다. 두 후보 모두 접촉을
오래 유지하지 못했고(1450 tick 중 42·188 tick만 두 군 동시 접촉, 힘 0.6–1.9 N),
이번 두 후보에서 필요한 접촉 유지에 실패했다. 76 mm 폭과 후보 형상의 부적합은
가설이며, 이 물체에서 모든 Pincer가 불가능하다고 단정하지 않는다. 다른 유형으로 넓혔다.

**정련 이후 정적 선별의 최대 탈락 사유는 테이블 관통이다.** 정련은 테이블이 없는 floating 장면에서
접촉을 최적화하므로, 필터가 확보한 테이블 여유를 다시 잃는다: 캔 165개 중 104개,

개선 후보이며 이번에 고치지 않았다. 이 파일 수만으로 전체 파이프라인의 최대
병목이나 테이블 인지 정련의 최종 완주율 개선을 확정하지 않는다.

## 3. 실행 결과

| 물체 | 실행 | 완주 | 리프트 시간초과 | 닫기 시간초과 | 명령 불가 | 접근 경로 실패 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 캔 | 32 | **1** | 9 | 2 | 17 | 3 |
| 카메라 | 17 | 0 | 7 | 5 | 5 | 0 |

카메라는 어떤 시도도 13.4 mm 이상 올리지 못했고, 닫기 시간초과 5건은 필요한 접촉군이
**동시에 성립한 tick이 0**이었다. `14_Tripod`는 최대 **3/3 군 동시 접촉이 78 tick**
성립했고 종료 시 **2/3 군**이었다(상승 13.4 mm). 앞서 최대 접촉과 종료 접촉을 혼동했다.
다른 리프트 시간초과 후보들도 전 군 동시 접촉을 만든 이력이 있다. 따라서 이 실행
집합의 병목은 접근 이후이며, **접촉 획득 실패·리프트 중 유지 실패·품질을 만족하는 명령을
찾지 못한 실패**를 구분해야 한다. 카메라 전체를 닫기 제어 하나의 문제로 단정하지 않는다.

## 5. 한계와 다음

- **완료 조건 미달**: 카메라 시범이 없다. 정적 통과(13건)를 완료로 세지 않았다.
- 캔도 1건이다. 학습에 쓸 만한 규모가 아니며, 유형 1개·yaw 1개·rest 1개다.
- 다음 후보(권장 순서): ① 정련을 테이블 인지 방식으로 바꾸거나 정련 후 테이블
  여유를 회복하는 보정 단계 — 지금 최대 누수 지점이다. ② 카메라의 다른 놓임 자세
  (CPU 사전 검토에서 rest 2에서 4개 통과)를 별도 조건으로 실행. ③ 닫기 제어를
  유형별로 점검(Power Disk는 되고 Parallel Extension은 안 된다). ④ 물체를 더 넓혀
  성공하는 형상·유형 조합의 분포를 본다.
- 이번에 병은 재실행하지 않았다. 기존 성공 기록과 체크포인트는 그대로 보존했다.
