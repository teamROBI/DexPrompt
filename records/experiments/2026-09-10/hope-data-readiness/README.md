# HOPE 물체와 다배치 시범 수집 준비 점검

2026-09-10 작업의 후속 점검, 09-11 정리. GPU 작업 없이 공식 자산과 현재 프로젝트의 메시·컴파일 모델을 확인했다.
새 teacher 생성, 파지 실행, 학습은 하지 않았다. 이 목록은 수집 후보이며 성공 데이터 목록이 아니다.

## 판단

HOPE를 다음 수집 대상의 주 자산으로 사용한다. 그릇·망치의 실패를 해결해야만
진행할 필요는 없다. 먼저 병·캔·상자에서 물체와 배치의 다양성을 확보한다.
HOPE는 물체의 3D 메시와 RGB-D/6D 자세 데이터이므로, VLA에 필요한 로봇 행동은
Dexonomy와 실행기로 새로 생성해야 한다. 28개는 식료품 **장난감**이며 제품 이름으로
실물 식품 용기의 크기나 질량을 가정하지 않는다.

출처: [공식 HOPE 저장소](https://github.com/swtyree/hope-dataset),
[공식 다운로드 목록](https://github.com/swtyree/hope-dataset/blob/master/setup.json).

## 실제 발견: 같은 HOPE라도 full과 eval 메시의 단위가 다르다

공식 설명은 메시 단위를 cm라고 쓰지만, 다운로드한 **full 묶음은 eval보다 좌표가
약 10배 크다**. 두 공식 zip의 MD5를 공식 setup.json과 대조한 뒤 28개를 모두 측정했다.

| 입력 | 미터 변환 | 검증 |
| --- | ---: | --- |
| 공식 `meshes/full/*.obj` | **0.001** | 28개 모두 eval의 미터 환산 치수와 일치, 최대 축 길이 차이 0.163 mm |
| 공식 `meshes/eval/*.obj` | **0.01** | 공식 cm 설명과 일치 |
| GraspGenX에 들어 있던 3개 OBJ | **0.001** | 공식 full의 해당 OBJ와 SHA256까지 동일 |
| 이미 만들어진 `assets/object/icra/*/mesh.obj` | **1.0** | 위 변환과 upright 회전이 적용된 미터 메시, 크기 차이 <0.00001 mm |

예: Mustard full의 축 길이는 65.13 / 160.05 / 48.57이고, eval은
6.51 / 15.99 / 4.85이다. **공식 README의 cm 설명을 full에도 그대로 적용하면
10배 커진다. 기존 프로젝트 3개의 0.001 변환은 맞았다.** BOP 등 다른 배포본에는
이 계수를 자동 적용하지 말고 별도 단위·해시 계약을 만든다.

파일은 `out/hope-audit/source/`에 원본 zip과 추출본을 보관했다. full 102,572,207 bytes,
eval 35,083,291 bytes. 이미지/영상 데이터셋은 다운로드하지 않았다.
28개 모두 텍스처 파일이 있고, 치수·해시·변환 계수는 [inventory.json](inventory.json),
전체 치수 표는 [dimensions.csv](dimensions.csv)에 있다.

## 그릇·망치 재측정

충돌 조각의 회전된 AABB를 합치는 대신 실제 시각 메시 정점에 스케일과 rest 0 회전을
적용했다. 아래 수치는 외곽 치수이며 손가락이 잡는 국소 영역의 두께가 아니다.

| 물체 | 설정 | 테이블 위 XYZ 외곽 치수 (mm) |
| --- | --- | --- |
| 기존 그릇 | 0.05, rest 0 | 69.8 × 70.0 × 21.7 |
| 확대한 그릇 | 0.08, rest 0 | 111.6 × 112.0 × 34.8 |
| 기존 망치 `ddg_gd_hammer_poisson_005` | 0.08, rest 0 | 122.3 × 113.7 × 27.9 |

망치는 누운 뒤 대각선으로 놓여 위 XY 치수가 나온다. 원래 메시 좌표계 외곽은
61.3 × 33.2 × 144.2 mm다. **둘 다 실제 제품 치수로 보정된 자산은 아니다.**
현재 자동 스케일은 OBB 중간 길이를 약 70 mm로 맞추는 규칙이다. 얕은 그릇의
림 높이와 망치 손잡이 두께를 직접 고려하지 않으므로, 자연스러운 크기나 적합한
파지를 보장하지 않는다. 이번에는 규칙이나 과거 자산을 수정하지 않았다.

## 데이터 수집 전에 처리할 실제 빈틈

1. **물리 자산은 3/28만 있다.** ChocolatePudding, GranolaBars, Mustard는 기존 충돌
   분해와 scene config가 있다. 나머지 25개는 원본 메시만 확보했으며 충돌 분해,
   안정적인 놓임 자세, 동일 테이블 조건을 만들어야 한다.
2. **텍스처가 렌더러에 연결되지 않았다.** 기존 3개 모델을 실제 컴파일해 확인한
   물체 visual geom의 material id가 전부 -1이다. `scene.build`는 동일한 RGBA를 쓰며
   텍스처 material을 추가하지 않는다. 파일에 포장지 이미지가 있어도 현재 student
   렌더에는 쓰이지 않는다. 별도 visual profile로 텍스처·UV·조명을 연결하고 렌더를
   확인한 뒤 새 시각 시범을 수집해야 한다. 기존 시범 재현 경로는 유지한다.
3. **0.1 kg 설정과 컴파일 질량은 다르다.** 기존 3개 실측 질량은 각각 0.10704,
   0.10834, 0.10933 kg다. `scene.OBJECT_MASS / asset.volume`으로 밀도를 정하지만
   충돌 분해 메시에서 적분한 체적과 asset 체적이 달라 정확히 0.1 kg이 되지 않는다.
   새 자산은 teacher와 실행기의 컴파일 질량·관성을 비교해 기록한다. 실제 장난감
   질량을 측정한 값이라고 주장하지 않는다. 이번에는 질량 설정도 바꾸지 않았다.
4. **다배치 정합 검사는 별도다.** 현 `check_placement.py`는 rest 0/yaw 0만 지원한다.
   파일명에 yaw를 붙였다고 다른 배치가 검증된 것은 아니다. 새 배치별 실제 물체
   변환·스케일·테이블·초기 로봇 상태·안정화 후 이동량을 단계 간 대조해야 한다.

## 첫 수집 묶음 제안: 6개 물체, 성공한 물체에 5개 배치

아래는 크기와 형상에 따른 **사전 선택**이며 파지 가능성의 검증 결과가 아니다.
upright는 기존 전처리와 같은 X축 +90°이고, 축 이름은 폭/깊이/높이다.

| 물체 | 폭 × 깊이 × 높이 (mm) | 선택 이유 |
| --- | --- | --- |
| AlphabetSoup | 66.1 × 71.1 × 83.6 | 높이가 있는 캔 |
| Peaches | 65.9 × 71.0 × 57.8 | 낮은 캔, 높이 차이 |
| Mustard | 65.1 × 48.6 × 160.1 | 기존 자산이 있는 병 |
| BBQSauce | 64.6 × 43.5 × 148.3 | 다른 병 형상 |
| ChocolatePudding | 83.5 × 29.9 × 49.5 | 기존 자산이 있는 작은 상자 |
| Raisins | 85.9 × 39.7 × 123.2 | 세로로 긴 상자 |

GranolaBars는 165.3 × 38.7 × 124.0 mm로 넓다. 파지가 불가능하다는 뜻은 아니지만
첫 묶음에서는 뒤로 둔다. 모든 HOPE 물체의 크기는 원본 물리 단위로 고정하며
손에 맞게 임의 축소하지 않는다.

실행 순서와 중지 기준:

1. 위 6개 자산의 단위·시각/충돌 정합·텍스처·놓임 안정성·컴파일 질량을 검증한다.
   이 단계가 끝나기 전에는 학습 데이터로 내보내지 않는다.
2. 중앙 배치에서 물체당 최대 2개 파지 유형을 사전 고정한다. 유형의 정식 템플릿과
   전체 요구 접촉군을 유지하며, 비교 정련 예산은 동일하게 400회로 고정한다.
   후보/템플릿/seed/실패 단계의 귀속과 실행 종료 코드를 남긴다.
3. 물체당 동적 실행 상한 12회, 총 최대 72회로 첫 수율을 잰다. 후보 없음,
   접근 실패, hold 중 낙하를 모두 기록한다. 소진된 물체의 제어 튜닝으로 넘어가지 않는다.
4. 중앙 배치에서 완주한 물체만 yaw 0/−15/+15°, XY 중심 및 X ±20 mm의
   **5개 독립 조건**으로 확대한다(전체 조합이 아님). 장면 중심은 현재 설정의
   (0.35, 0.0) m, 테이블 높이 0.8 m이며, 도달성과 시야는 아직 미검증이다.
   배치가 바뀌면 접근·닫기·리프트·hold를 다시 실행해서 성공한 시범만 채택한다.
5. 파일 수 대신 성공한 고유 물체 수, 물체×배치 수, 고유 teacher 수, 시간당 채택
   시범 수를 보고한다. 첫 운영 목표는 **4개 이상 물체에서 각각 3개 이상 배치**다.
   이것은 수집 파이프라인의 파일럿 기준이며 논문 규모의 일반화 증거가 아니다.
6. 위 단계가 통과하면 3개 물체가 함께 있는 약한 clutter 장면으로 진행한다.
   같은 장면에서 목표 mask만 바꾸어 각각 다른 물체를 잡는 시범을 균형 있게 모은다.
   단일 물체 시범을 다시 렌더하는 것만으로 방해물 속 파지 성공을 가정하지 않는다.

일반화 평가에서는 **미사용 배치**와 **미사용 물체**를 분리한다. HOPE의 포장만 다른
유사한 캔을 train/test로 나누면 외형이 새로운 것과 기하가 새로운 것을 혼동할 수
있으므로 형상 유사군도 함께 보고한다. HOPE에는 우리 손의 행동이나 손잡이/기능적
부위 정답이 없으므로 mask→point/text 확장은 별도 목표 지정 계약과 평가가 필요하다.
핸들·도구 파지의 장점은 추후 실제 치수가 확인된 별도 물체로 검증한다.

## 검증 범위와 재실행

공식 zip 체크섬, 28개 full/eval 치수 정합, 기존 3개 입력의 내용 해시와 변환,
기존 3개 실제 모델 컴파일, 그릇/망치 스케일 측정을 수행했다.
접근 IK, 렌더 가시성, 놓임 안정화, 파지 성공은 이 감사에서 검사하지 않았다.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 CUDA_VISIBLE_DEVICES='' MUJOCO_GL=osmesa \
  PYTHONPATH=src nice -n 15 third_party/dexonomy/.venv/bin/python \
  results/2026-09-10/hope-data-readiness/audit.py
```

lecun 단일 병 학습도 종료된 것을 읽기 전용으로 확인했다. 6,331회 갱신 후
사전 지정 마지막 epoch 13의 완주는 0/3이며 중간 4개 checkpoint도 각각 0/3이다.
손실 감소만으로 시각 행동 전이를 확인했다고 하지 않는다. HOPE 자산 준비는 계속할
수 있지만, 새 데이터가 이 문제를 자동으로 해결한다고 가정하지 않는다.
평가 요약은 [completed-summary.json](../single-bottle-student/completed-summary.json)에 있다.
