# 추론 단계16 대50 비교 — 완료

**50단계로 늘려도 초기 행동 생성 오류는 해결되지 않았다.** 고정24쌍 모두 첫 행동
최대 오차와 첫8개 팔 행동 RMSE가 증가했다. 이 checkpoint에는50단계 변경을 채택하지
않고 기존16단계를 유지한다. 새 학습과 물리 실행은 하지 않았다.

## 단일 요인과 입력 보존

사용자의 실행 승인 뒤 [plan.json](plan.json)을 고정했다. A는 이전
[teacher 관측 진단](../teacher-observation-diagnosis/README.md)의24개를 재사용했고,
B만8시점×3seed=24개 생성했다. 시점0/8/16/32/64/200/450/700,
seed1000/1001/1002를 각 시점에 독립 초기화했다.

- 고정 x0 checkpoint `epoch_0012.pt`, SHA256 `a5100b38f9c1fb64…`.
- 설정은 `inference_steps` 16→50 하나만 달랐다. 같은 `predict_action()`으로 실행하며
  B의 단계는49,48,…,0 전체50개다. 학습 diffusion_steps50, horizon64, clipping,
  DINO, 정규화, 모델 구조는 그대로다. 원본 모델 소스·checkpoint 파일은 미수정.
- 8관측 해시, 원본 dataset 해시,24개 정답 행동 및 action_scale이 A/B에서 같다.
  모든 관측에서 online/cache 입력 텐서도 일치한다.
- 모델 전체 상태 해시가 A/B 및 B 실행 전후 같다. backward/optimizer 갱신은 차단했다.
- lecun GPU1 tmux `dexprompt-sampler50-v1`에서 B 진단81.5초, exit0.
  완료 후 tmux 종료 확인. 기존 helper를 보존하고 원격에서는 `_50.py`라는 새 이름 사용.

## 전체 시점 결과

아래는 각 시점3seed의 중앙값이며 단위는 rad다. 첫 행동 최대 오차는27관절 전체에서
최대인 값, 팔8행동 RMSE는 첫8행동×팔7관절의 오차다.

| 8 | 0.08419 → 0.09370 | 0.02677 → 0.03119 |

- 첫 행동 최대 오차: **0/24 개선,24/24 악화**.
- 첫 행동 팔 RMSE와 첫8행동 팔 RMSE도 각각 **0/24 개선,24/24 악화**.
- 전체64행동 팔 RMSE:8/24 개선,16/24 악화. 일부 묶음 전체가 나아졌어도
  실행에 먼저 쓰는 앞8개가 좋아지지 않았다.
- 손 RMSE: 첫1/8/64행동에서 각각13/24 개선,11/24 악화.
  손 구간별 절대 오차는 [comparison.json](analysis/comparison.json)에 모두 보존했다.
  따라서 모든 관절·모든 지표가 악화됐다고 일반화하지 않는다.

## 판단과 다음 작업

**추론 단계 수를 늘리는 것만으로 해결되지 않는다.** 이는 이 고정 checkpoint와
선택한 teacher 관측에 대한 결과이며, 다른 모델이나 다른 관측까지 일반화하지 않는다.
샘플링 관련 문제가 전혀 없다는 증명도 아니다. 학습 단계나 손실의 문제로 원인을
확정하지 않았고, 물리 성공률을 새로 측정하지도 않았다.

다음 후보는 같은 x0 모델에 대해 **정답 행동에 고정 잡음을 넣은 단일 단계 예측과
실제 순수 잡음 생성 경로를 비교**하는 무학습 진단이다. t=0/25/49에서 팔·손 및
첫8/전체64 오차를 나눠, 네트워크의 x0 추정 자체와 반복 생성 중 오차 변화를 분리한다.
이는 이전 epsilon 모델의 진단과 다른 checkpoint에 대한 검사다. 정답 행동을 넣는
진단은 실제 정책 성능으로 세지 않는다. 아직 실행하지 않았다.
새 HOPE 학습·horizon/손실 변경·샘플러 단계 탐색을 자동으로 시작하지 않는다.
