# HOPE의 근접 형상과 평가 분할 주의

2026-09-11. 데이터 인수/분할 준비의 읽기 전용 검사다. 새 자산·파지·학습은 생성하지 않았다.
공식 full 메시28개의 기존 감사 SHA256을 확인하고 각각8192표면점을 고정seed로 뽑았다.
좌표는 공식 full의 mm 단위 그대로이며 bbox중심만 맞췄다. 회전 정합이나 스케일 변환은 없다.

축별bbox차 최대3mm, 양방향 최근접 표면샘플 거리 평균≤2mm·95백분위≤4mm를
**검토용 근접 판정**으로 미리 설정했다. 21개 쌍이 조건을 만족했다. 이는 메시의
동일성 판정이나 grasp 난이도가 같다는 증명이 아니다. 샘플링·축 정렬에 따른 오차와
미검출이 있고, 연결 성분의 모든 쌍이 서로 근접하다는 뜻도 아니다.

주요 근접 그룹:
- AlphabetSoup / TomatoSauce
- Cherries / Corn / GreenBeans / Peaches / PeasAndCarrots / Pineapple
- BBQSauce / Ketchup
- Butter / CreamCheese
- Cookies / MacaroniAndCheese
- Milk / OrangeJuice
- Mushrooms / Tuna

따라서 "Peaches를 학습하고 Corn을 테스트"했다는 사실만으로 새로운 **형상**에
일반화했다고 주장하면 안 된다. 목표로 하는 일반화가 새 외관/상품인지, 새 배치인지,
새 형상인지 나누고 해당 그룹을 평가 단위에 맞게 분리해야 한다.

이번 3물체를 포함해 이미 개발에 사용된 HOPE 7개와, 같은 근접 그룹의 물체를 합친 총 14개를
`development-exclusions.json`에 적었다. 남은14개를 자동으로 test에 할당하지 않는다.
근접 검사에 걸리지 않았다고 형상이 다르다고 보장할 수 없고, 추가 geometry 검토와
최종 과제 정의가 필요하다. 현재 시범은 모두 개발용이며 독립 test 없음이라는
기존 데이터 계약을 유지한다. 초기 물체 이름 수와 형상 다양성을 분리해 집계한다.

`geometry.json`: 모든 입력 해시·샘플seed·수치·그룹.
`audit.py`: CPU1thread 재현 스크립트. 충돌 자산이 아니라 시각 표면 메시 비교다.
