# HOPE 새 후보 C0–C3 교차 확인

2026-09-11. Claude 원본 출력과 고정 student 7시범은 수정하지 않았다.
`audit.json`에 ledger/실제 파일 대조와 저장 신호의 student guard 검사를 기록했다.

## 확인된 결과

- 24회 = 기존 대조군 3 + 새 중앙 12 + 중앙 재현 2 + 배치 4 + 배치 재현 3.
- 24회 모두 실제 episode·모델·초기 상태 파일 SHA256이 ledger와 일치한다.
- 새 중앙 성공 AlphabetSoup 1/4, Peaches 0/4, Raisins 2/4. 배치 성공 3건을 합쳐
  새 승인 6건, 새 고유 후보 3개, 물체 2개, 물체-배치 조건 5개, 유형 2개다.
- 새 후보 12개는 이전 제외 목록과 겹치지 않으며 source 파일 해시가 맞는다.
- 기존 대조군 3개 episode는 원본과 같다. 새 승인 중 5개는 재현본과 episode·모델·
  초기 상태 해시가 같다. Raisins `438146b5` 중앙은 미재현이므로 별도 대기한다.
- 첫 HOPE ledger의 물리 시작 행 61개와 입력 거절 행 12개를 확인했다. 61은 비용,
  48은 최종 유효 새 조건 수다. 부분 시작의 결과를 성공/실패로 추정하지 않는다.

## 보고 해석 수정

공통 분류의 `carry`는 실제 실행 phase가 아니다. 접촉군이 한 번 모두 성립한 뒤
사라졌다는 `contacts_taken_then_lost`를 포함한다. 새 중앙 실패 9건의 실제 phase를
읽으면 **8건은 close에서 종료, 1건만 lift에 진입**했다. 따라서 기존 `닫기 5 / 운반 4`는
`모든 접촉군 동시 성립 없음 5 / 성립 경험 후 상실 4`로 읽어야 한다.
세 건의 close 종료를 리프트 하중 유지 실패로 해석하면 안 된다. 분류 코드나 과거
teacher 판정은 이번 검토에서 바꾸지 않았다.

Raisins `3e8fa799`는 지정 조건에서 기존보다 침투 여유가 커진 사례다. 그렇다고 새
형상보다 접촉 제어 진단을 반드시 먼저 해야 한다는 결론은 나오지 않는다. 이번에는
기존 풀이 있는 세 용기 물체만 시험했다. 시각 정책 이탈 진단과 다른 형상 시범 확보는
별도 축으로 진행할 수 있다.

## Student 인수 사전 검사

`watch_visual_intake.source_guard()`를 재사용해 여섯 원본 episode의 저장 신호를
검사했다. 최소 접촉력과 0.5초 연속 획득 조건이 포함된 기존 guard에서 **6/6 위반 없음**.
새 AlphabetSoup 중앙도 통과했다. Claude의 힘 조건 없는 XY 대리 지표 대신 실제
student guard 로직을 사용했다.

이 검사는 저장 신호 기반 사전 기각 검사다. 실제 시각 profile로 다시 렌더하고
관측 정렬·목표 기억·기록 행동/정지 대조군·preflight를 통과해야 student-ready다.
재현된 5건은 다음 별도 인수 묶음 후보이고, `438146b5`는 재현 확인이 먼저다.
