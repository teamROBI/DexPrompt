## 2. 배치 계획 (실행 전 고정)

- 방해물: A 설정에서 초기 장면 안정화가 검증된 HOPE 물체는 AlphabetSoup·Peaches·Raisins뿐이므로, 목표를 뺀
  나머지 두 물체를 (AlphabetSoup → Peaches → Raisins) 순서로 쓴다. 첫째는 목표 기준 **(0, +0.13 m)**, 둘째는
  **(0, −0.13 m)**. scene의 yaw(0)를 공유한다.
- 조건: 단일 물체 대조군 / 방해물 1개(첫째) / 방해물 2개(둘 다). 목표의 위치·yaw·teacher 목표는 그대로다.
- `icra.scene.build`는 좌표 없는 여러 물체를 0.18 m 간격 한 줄로 늘어놓아 목표까지 옮기므로, 수집기에는
  실행 범위 패치로 **목표 (0, 0), 방해물 고정 좌표**를 넘긴다. 좌표 파일에 없는 물체는 오류로 멈춘다.
- 사전 검사(물리 예산 외): 목표 초기 자세 = 단일 물체 자세, 초기 겹침 없음, 모든 물체 기존 안정화 기준
  (이동 ≤ 5 mm·회전 ≤ 5°·선속도 ≤ 0.005·각속도 ≤ 0.05), 로봇–물체 침투 없음, 목표 참조 가능(머리/손목 중
  하나), multiccd 꺼짐. **탈락한 조건은 옮기지 않고 제외해 따로 집계한다.**

## 3. 예산

물리 실행 최대 **15회**: 대조군 재현 3 + 새 조건 6 + 새 조건 성공의 동일 조건 재현 최대 6. 시뮬레이션을 시작한
실행은 인프라 실패·재시도라도 차감한다. 대조군이 원본 episode 해시로 재현되지 않는 물체는 후속 실행을 멈춘다.

## 4. 판정 기준과 집계 확인

- 기존 품질 판정 그대로. 방해물 관련 기존 항목도 그대로 적용된다: 로봇–방해물 침투 > 1 µm이면
  `robot_obstacle_collision`, 방해물 이동 > 10 mm이면 `non_target_displacement_limit`. 손가락 힘 합계에는 목표·
  테이블·방해물 압력이 모두 들어간다(기존 정의).
- **목표 접촉군은 방해물 접촉으로 채워지지 않는다.** `ContactMeter`는 접촉 상대가 목표 물체 subtree일 때만
  접촉군을 켠다. 합성 MuJoCo 모델로 확인하는 회귀 검사를 추가했다: 손가락이 방해물에만 닿으면 목표 접촉군
  꺼짐·로봇–방해물 침투 > 0, 목표에 닿으면 접촉군 켜짐·방해물 침투 0 (`tests/test_hope_clutter.py`).

### 목표 접촉군 집계 확인

- 코드: `ContactMeter`는 상대가 목표 subtree일 때만 접촉군을 켠다. 합성 모델 회귀 검사(`tests/test_hope_clutter.py`)로
  방해물 접촉이 목표 접촉군을 켜지 않음을 확인했다.
- 데이터: 성공한 Raisins 4회(원본·재현)는 로봇–방해물 접촉이 0 tick이라 방해물이 접촉군 판정에 들어갈 여지가 없다.
  방해물에 닿은 AlphabetSoup 2회는 목표 접촉군이 0으로 남았다 — 방해물 접촉으로 접촉군이 채워진 사례는 없다.

## 결론

- 기존 teacher 시범 3개 중 **Raisins `3e8fa799`는 방해물 1·2개 옆에서도 실행 가능**했고 동일 해시로 재현됐다.
- **AlphabetSoup `1443cca6`은 닫기에서, Peaches `203b95f1`은 접근 경로 검증에서** 이 배치의 방해물 때문에 실패했다.
  실패 지점이 물체마다 다르다.
- 표본은 조건당 1회다. 성공률 우위나 clutter 일반화를 주장하지 않는다. 이 결과는 "기존 시범이 가벼운 clutter에서
  실행 가능한지"에 대한 물체별 1회 관찰이다.
- 지시대로 후보 확대·재정련·제어 변경·기준 완화·방해물 재배치 없이 이 예산에서 종료한다.
