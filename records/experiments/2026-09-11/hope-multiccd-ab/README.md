# multiccd 비교 실험 (별도 물리 설정)

2026-09-11, **완료 (21:54)** — multiccd는 실패 물체의 흔들림을 줄였지만 계약을 지속적으로 통과한 것은
Milk 1개, 기존 파지 3개 중 Raisins는 B에서 실패. 기본값 채택 안 함. 사용자 승인 범위: **비교 실험만.** 기본 물리 설정, `scene.py`·Recorder·수집기,
충돌 분해, 마찰·기준, 기존 데이터·student 파일은 바꾸지 않는다. 새 파지 생성·학습 없음.

- A = 기존 설정. B = 같은 컴파일 모델에 MuJoCo `mjENBL_MULTICCD` 한 비트만 켠 것.
- B는 실행 범위 안의 패치로만 적용한다: [collect_multiccd.py](../../../../scripts/teacher/collect_multiccd.py)가
  `icra.scene.build`가 컴파일한 모델에 **컴파일 직후** 플래그를 켠다. Recorder의 로봇 자세 보정(brace),
  안정화, 기록이 모두 그 뒤에 일어난다. 디스크의 코드·기본값은 그대로다.
- 도구: [compare_multiccd.py](../../../../scripts/diagnostics/compare_multiccd.py) (`static`, 조건부 `grasp`).
- 출력: `/data1/yspark/sim/icra/hope-multiccd-ab-v1`.

## 결론

1. **multiccd는 실패 물체의 테이블 지지 접촉점을 실제로 늘리고 흔들림을 줄인다.** 한 비트만 바꾼 개입에서
   관찰됐다. 그러나 기존 초기 장면 계약을 1.2 s와 지속 기준 모두로 통과한 것은 **Milk 하나**이고, Mayo는
   1.2 s 한 시점만, Butter·Spaghetti는 탈락이다. 접촉점 부족 가설은 "기여 요인"으로 지지되지만 전부를
   설명한다고 하지 않는다.
2. **multiccd는 파지 동역학도 바꾼다.** 기존 성공 후보 3개 중 1개(Raisins)가 B에서 실패했고, 나머지 2개도
   품질 여유가 달라졌다. 테이블 안정화 개선과 파지 성능 변화는 방향이 다르다.
3. **기본값으로 채택하지 않았다.** 기본 설정·코드는 그대로다.

채택을 검토하려면 먼저 정해야 할 범위(이번에 실행하지 않음):

- **정련기·실행기 설정 일치**: Dexonomy 정련 환경(`MuJoCo_OptEnv`)이 같은 접촉 생성 설정을 쓰는지 확인하고
  맞추지 않으면, 정련에서 통과한 자세가 실행기에서 다른 접촉을 겪는다.
- **brace 차이**: B에서 로봇 자세 보정 명령이 달라지므로, 로봇 초기 자세 오차 계약을 다시 확인해야 한다.
- **기존 성공 자료 재검증**: 첫 HOPE 8건·후보 다양성 6건·Raisins 재현, 그리고 student 인수 7건(원본 A 물리로
  생성·재생 검증됨)을 B에서 다시 실행해 몇 건이 유지되는지. Raisins 사례처럼 성공이 바뀔 수 있으므로
  기존 student 데이터와 B 물리를 섞지 않는 분리 규칙이 필요하다.
- **판정 기준**: 안정화 기준(1.2 s와 지속)은 그대로 두고, B에서 통과하는 물체만 새 형상 후보로 쓸지.
