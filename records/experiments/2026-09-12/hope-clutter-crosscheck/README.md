## AlphabetSoup 해석 수정이 필요한 부분

원본 NPZ의 `digit_force_max`와 해당 실행 `sources/src/icra/execution.py`를 확인했다.
보관 코드 해시는 collection 기록과 일치한다. 코드에서 요구 접촉군/접촉력은 목표 물체에서만 읽고,
닫기 중 외력을 우선 적용하는 조건은 `max_digit_force * penetration_margin = 30 * 0.75 = 22.5 N`이다.

| 조건 | close tick | 최대 외력 N | 22.5 N 초과 tick | 요구 접촉군 최대 | 기록된 guard_scaled_ticks |
| --- | ---: | ---: | ---: | ---: | ---: |
| 단일 대조 | 130 | 29.9422 | 28 | 5 | 28 |
| 방해물1 | 600 | 0.002712 | 0 | 0 | 560 |
| 방해물2 | 600 | 0.383212 | 0 | 0 | 560 |

따라서 **방해물 압력이 곧바로 목표 접촉으로 오인되어 닫기를 막았다는 해석은 지지되지 않는다.**
모든 외력을 합산하는 이유 자체는 과부하 보호이므로, 해당 합산을 제거하거나 기준을 완화하지 않는다.

`guard_scaled_ticks=560`은 명령 미리보기에서 축소가 반복됐다는 더 직접적인 단서다.
하지만 축소된 명령의 종류/비율/거부 body pair와 예측 침투는 이 숫자에 없으므로,
방해물 충돌 예측이 원인이라고 확정하지 않는다. 필요한 경우 보관 코드의 실행을 재현하며
guard 분기만 계측한다. 명령 기록 재생만으로 미리보기 내부 결정을 복원했다고 주장하지 않는다.
요구 접촉군0과 로봇 전체의 목표 접촉 부재도 구분한다.
